## 本机 Node 版安装与启动

需要 Node.js 22 或24、pnpm 11。Windows 已在 Node 24.19.0 / pnpm 11.19.0 实际验证。依赖版本锁定在 pnpm-lock.yaml。

项目实际目录为 `D:\文字游戏`；先在 PowerShell 执行 `Set-Location -LiteralPath 'D:\文字游戏'`，再运行下面命令。原目录仅留迁移说明，备份目录不是开发目录。现有主档仍在 `C:\Users\13710\DayaoNovel`。

    pnpm install --frozen-lockfile
    pnpm dev

打开 http://127.0.0.1:3000 。默认只监听本机。若 npm 官方下载在当前网络超时，可在安装时明确指定镜像：

    pnpm install --frozen-lockfile --registry=https://registry.npmmirror.com

本机运行生产构建（仍依赖这台电脑，不代表已完成公网生产部署）：

    pnpm build
    pnpm start

可在 .env.local 设置 APP_PORT，或在 PowerShell 中设置 $env:APP_PORT="3001" 后启动。默认本机模式不需要账号或 OpenAI Key；局域网／公网模式需要个人登录口令。不依赖远程字体或云端数据库。Playwright 在 Windows 使用本机 Edge；其他系统先执行 pnpm exec playwright install chromium。

## 手机访问、PWA 与离线

详细运行和排障步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。标准启动为 `pnpm start`，保留该终端；生命周期日志自动写入 `APP_DATA_DIR/logs`。后台 PowerShell 脚本是可选方式，当前电脑的脚本执行策略及自动审批阻止了这一方式，未修改系统策略。浏览器打不开时先检查服务和3000端口；网页不会自己启动 Node。

- **本机／LAN**：电脑运行服务，手机访问同一Wi-Fi下电脑的IP，不能访问电脑的localhost；电脑仍需保持运行。显式配置 `APP_ACCESS_MODE=lan`、`APP_ORIGINS`，用 `pnpm password` 生成个人口令哈希。
- **当前公网方案**：GitHub Pages 静态浏览器版，保留统一 Next.js／TypeScript、原游戏规则、三个模型适配器和存档格式。浏览器 SQLite WASM + IndexedDB 是 Pages 主存档；没有后台服务器、统一 Key 或跨设备自动同步。Sites、Vercel 和持久服务器方案属于先前评估／备选，不是此次发布平台。
- **存储位置**：本机版主库仍在电脑的 DayaoNovel；Pages 版主档在当前浏览器 `interactive-fiction-pages-v1` IndexedDB。二者不自动互相迁移，同一 Pages 的不同浏览器不自动同步。
- 在设置中点击“下载此存档供离线阅读”，完整下载当前卷册的全部分支、节点原文和对应人物状态，显示同步时间与版本。检查所有分支、原文和逐节点人物簿完整后才原子替换；较早的请求晚到、下载不完整或空间不足时保留原副本。断网可以阅读、查状态、保存未发草稿及导出完整下载；不能调用模型或提交正式剧情。
- 网络恢复、刷新或回到前台先查询原请求ID，不自动重发生成。未知结果可手动重发同ID；提交冲突保留草稿、由你刷新或另开分支，不自动合并故事。
- 支持的浏览器在设置中显示安装入口；在故事页收到的安装提示也会保留到打开设置时。已在独立窗口启动时识别安装状态；没有入口时按Safari分享／Chrome菜单添加到主屏幕。安装不是游玩前提。手机LAN HTTP通常不能安装Service Worker；离线启动需要有效HTTPS，电脑localhost可用于本地验证。
- 阅读位置、当前卷册／分支、未发输入与排版偏好自动记住。切换卷册前立即保存最后输入，慢返回的旧卷册请求不会覆盖后选的卷册。故事／往事按20节分页展示；返回故事恢复位置，向上读时只提示有新内容。“字”中可选择浅色、深色、护眼主题。当前仍一次读取所选分支的数据，分页限制的是正文渲染；尚未做超大存档网络分页和十万节点性能验收。
- 离线副本不会自动回写服务器；更新不清空主档或浏览器存档。完整离线包含恢复用隐藏资料，仅在自己的设备下载。浏览器可能清理数据，请保留JSON或SQLite外部备份。
- 应用更新需主动点击；有未发送输入、正在生成／查询原请求、下载副本或编辑正文时，更新按钮暂不可用。更新前会保存输入状态；其他标签页更新也不会强制刷新当前阅读页。若同一卷册的服务来源改变，先导出旧副本并移除，再重新下载，不静默替换来源。

## 开始故事

打开“剧本库”，选已安装版本“开始新游戏”；也可在“存档”选择剧本再“开始新故事”。新档绑定该版本快照，编辑或安装新版本不会改旧档。固定序章直接显示、不调用模型；条件生成开局需点击“生成第一幕”。自定义／可选择主角先在新档表单填写。

选择内置大曜时，初始御书房仅玄天华在场，门外身份未明；17% 是账目疑点，批注尚未送达。六名 NPC 的信任、好感严格使用原设定。以下任免、双轨和朝局描述仅适用于这个剧本；其他世界使用自己的标签、规则和数值，关闭关系后不显示空零值。

默认使用 **Mock 离线演练**。它接受自由输入、演练召见与联络、保留玩家原文和记忆，供验证交互、规则与数据链路；其有限示例文案不代表真实模型创作能力。连接真实供应商后自由续写才由对应模型生成。

- 自由输入对白或行动，Enter 默认换行，点击发送提交；中文选词回车不发送。
- 建议默认收起；点击“生成本段建议”后，由当前正文模型根据最新可见段落生成3–4条建议。选中只填入输入框，仍可改写，点击发送才执行。切换分支或段落会清除旧建议；未保存草稿作为独立参考，不成为正史。
- 选择在场角色作为主要交谈对象。不在场人物先选择召见、前往、寻访或书信，不会因点击头像到场。
- OOC 开关或 OOC: / OOC：前缀独立保存，不更新时间、关系、事件或人物记忆。文风偏好在设置中选择。
- 新生成内容先是草稿，显示收到的字符数、正文结束标志及当前阶段等待时间。正文完整而记忆整理失败，可只重试整理；截断或未记录结束状态的旧草稿，需先“核对／修订正文”并确认完整，或重新生成。正文、记忆与校验通过后才正式保存。重试和生成建议可能产生额外请求费用。
- 整理超时后，草稿下方会显示上次实际使用的模型。可展开“调整重试模型与等待时间”，在“此次记忆整理模型”选择当前配置，必要时把“此次整理等待”改为180–300秒，再点“重试整理并自动保存”；保留完整正文，单次设置不改全局配置。只保存模型设置不会暗中切换旧草稿使用的供应商。修订正文后点击“保存修改并自动整理”则采用弹窗显示的当前配置。
- 默认自动保存：输入后系统生成正文、整理记忆、校验并一起保存为正式剧情，无需逐节确认或手填记忆。整理失败时可点“重试整理并自动保存”，无需再审批；失败、截断或剧情冲突仍明确保留为草稿。
- API不可用时，可展开“手动整理记忆（高级补救）”，进入“本地审阅并保存”：核对正文、勾选实际在场人物、至少添加一项记忆及逐字来源，标明实际知情者，点一次保存即可，无额外确认框。按钮旁列出缺少的正文或记忆；“添加记忆”定位到新增输入框。新配角可在同一表单登记，默认无恋爱线。此路径不调用API；时间、地点与关系数值保持原样，用原有校验和事务保存，正式节点注明“记忆经本地审阅”。涉及任免、身份揭露、关系履历、远方人物收信或转场的复杂段落仍需模型整理，不能用此入口丢弃已有的复杂提案。
- 正文由玩家决定：措辞和疑似代演检查仅作为参考提示，不阻止自动保存，也不要求逐条确认。已保存正文下的“本节提示”默认收起，随时可用“修改”调整；模型仍被要求不替玄天华做决定，任免、人物知情与实际状态变化仍须有来源和授权。
- 整理模型仅缩写天气或没有提供新天气依据时，沿用上一节天气；普通剧情被误填为预设事件、待办摘要没有对应来源时，保留有来源记忆，不强行改变预设事件或新增无依据待办。处理说明随正式节点保存，可展开查看，不反复要求玩家确认。
- 对旧版留下的完整草稿，如果记忆结果已经收到，会出现“保存这段剧情”：使用已有结果在服务端核对并一次保存到主存档，**不调用模型 API、不增加模型费用**。正文不被自动改写；来源错误、无授权任免、并发进度冲突等仍会明确报错。没有完整整理结果时继续使用“重试整理并自动保存”或高级本地审阅。
- 想让模型调整措辞时，可展开“可选：让模型修正文”，点“自动修正并保存”。使用当前正文配置修正一次，再整理记忆并保存；真实服务可能计费。文字提示仍不构成保存门槛，不会循环修正。原稿保留于SQLite草稿记录和完整数据库备份；正式存档JSON及阅读版只导出已采用剧情。
- 已保存段落旁有“修改”按钮，可修改正文或改写输入。点“保存修改”或“重新生成并保存”后，自动从该节之前建立修订分支并整理保存，无须另填分支名称或再确认。取消不创建分支。原分支与旧未来保留，只有新分支采用的新节点参与后续记忆；固定序章保留原文。
- “这不是我的行动 / 人物忘记前情 / 时间跳太快”走父节点分支纠错。程序只做有限语义启发式检查，不保证任何模型永远不越权。
- 人物与朝局详情、卷册栏可折叠；“字”调整字号、行距、栏宽；右上切换明暗。浏览旧文时不强制跳到底部。

## 供应商与密钥

Pages 网页版在“设置”填写自己的 Key，默认勾选“在此设备记住 API Key”，保存在当前浏览器的独立 IndexedDB 密钥库，刷新或重新打开会自动使用。取消勾选并保存可改为仅本次页面使用，也可点击“清除这项密钥”。密钥不进入故事数据库、存档导出、缓存、仓库或构建产物，不会跨设备同步；清除网站数据会删除本机密钥。没有服务器环境变量或 GitHub Secrets。下面的服务端密钥和环境文件说明适用于保留的本机 Node 版。

在设置中编辑供应商配置，填写模型和密钥，先保存，再选择正文配置与可选记忆整理配置。默认正文、整理用同一模型。切换模型沿用本地历史，在途请求使用开始时的配置快照。

手机与电脑使用同一配置入口。即使现有条目已被改成其他供应商，“增加配置”后选择Google AI仍会带入原生Gemma默认模型；不会要求额外的OpenAI Key，也不会改写你已有的配置。

| 供应商 | 实际接入 | 默认模型 |
| --- | --- | --- |
| 硅基流动 | https://api.siliconflow.cn/v1/chat/completions，Bearer | 空，必须由用户选完整 ID |
| DeepSeek 官方 | https://api.deepseek.com/chat/completions，Bearer | deepseek-flash；可手填 |
| Google AI Gemma | 官方 @google/genai、原生 generateContent、user/model 与 systemInstruction | **gemma-4-26b-a4b-it** |

Google 不经过 OpenAI 兼容代理，不要求 OpenAI Key，不自动替换成 Gemini。三家密钥相互独立，无自动跨供应商回退。模型列表显示不代表账号具备生成权限。

设置页输入 Key 后提交实际运行的服务端并清空表单。默认只在服务进程内存中存在，重启需重填；不进 SQLite、浏览器持久化、导出、常规日志或前端 bundle。

可选：复制 .env.example 为 .env.local，只填写需要的字段：

    APP_PORT=3000
    APP_DATA_DIR=C:/Users/你的用户名/DayaoNovel
    SILICONFLOW_API_KEY=
    DEEPSEEK_API_KEY=
    GOOGLE_AI_API_KEY=

**.env.local 是本机明文，不是加密凭据库**，已加入 Git 忽略。不要使用 NEXT_PUBLIC_ 密钥字段。更改环境变量需重启服务。

Google 优先读取服务端 `GOOGLE_AI_API_KEY`，兼容已有 `GOOGLE_API_KEY`；内存中的该配置专用密钥优先于环境变量。`.env.example` 与 `.env.production.example` 仅含空变量名。Pages 不读取这些服务器配置，不需要 GitHub 模型环境变量；不应把站长 Key 写进静态构建。未采用的 PostgreSQL 适配代码已移出发布源码，`DATABASE_URL` / `AUTH_SECRET` 不用于 Pages。以下密钥与数据库命令仅适用于本机 Node 版。

“测试连接”“测试 JSON 能力”是两个独立按钮，使用无真实剧情的小输入，真实供应商会明确确认网络请求与可能费用；测试不创建故事节点。本次开发只运行 mock HTTP / SDK 契约测试，没有使用真实 Key，也没有真实 API smoke test。

高级能力按供应商、官方 endpoint、模型分别记录。Gemma 流式、原生 JSON schema 未实测，保持 unknown，默认非流式正文与纯文本 JSON 整理。DeepSeek 的已知协议支持流式和 JSON Object。未知能力不发送未经确认的思考、采样或 schema 参数。任何正文截断、拒绝、空返回均不提交。Google SDK 禁止隐藏自动重试；Chat Completions 最多一次短暂错误重试，并尊重 Retry-After（超过10秒转为手动重试）。

正文与记忆整理分别使用一次“请求超时”预算。非流式模型往往在生成结束后才发回响应头，因此生成请求不再受15秒响应头期限限制。流式请求另有“流式首字等待”设置，思考内容和心跳不算正文字；流式正文须同时收到正常结束原因与结束帧。达到 token 上限或连接中断时保留收到的草稿，并显示失败阶段。调整等待时间和输出上限后，重试同一供应商、同一模型时会采用新值，不自动切换模型。

硅基流动按官方 Chat Completions 基础字段发送已配置的 max_tokens；JSON Schema、流式和思考控制仍按具体模型能力决定。输出 token 上限不等于汉字数，篇幅目标只作为写作提示。行动建议是独立的按需请求，格式错误最多修复一次，不修改故事、人物记忆或游戏日期；模型的具体建议质量仍需真实使用时判断。

## 数据路径、备份与恢复

未设置 APP_DATA_DIR 时，数据在用户主目录的 DayaoNovel 中。本机为：

    C:\Users\13710\DayaoNovel\dayao.sqlite
    C:\Users\13710\DayaoNovel\backups\

实际绝对路径显示在设置页。数据独立于 node_modules、.next、浏览器缓存和源代码。正式正文只存一次，节点中保存快照；事实、认知、记忆、摘要有来源索引，分支可见性沿 parentTurnId 追溯。

每10个正式节点用 SQLite 在线备份生成快照，最多保留10份自动备份；设置页“立即安全备份”和以下命令生成独立保留的手动备份：

    pnpm backup

不要在 WAL 活跃时只复制 dayao.sqlite 主文件。使用上述在线备份，或完全停止服务后复制整个数据目录。

恢复完整备份时先停止服务，恢复到**新的空数据目录**：

    pnpm restore "C:\Users\13710\DayaoNovel\backups\manual-某次.sqlite" "C:\Users\13710\DayaoNovel-Restored"
    $env:APP_DATA_DIR="C:\Users\13710\DayaoNovel-Restored"
    pnpm start

## 日期、导入导出与参考

时间从剧本的 CalendarDefinition 读取，支持公历、可配置架空历、相对天数和关闭时间。内置大曜每年12月、每月30日，默认三月二十八日23:00，这是产品默认，原设定只给三月末深夜。新档高级设置可改日期和当前剧本世界数值，不追溯影响旧档。消息数、场景数、游戏日期分开计算；大曜财政是指数而非实际银两。

“往事”支持游戏日期（如 1-4-1）、含/不含截止当日、现实记录日期、人物、地点、关键词、书签与回看分支。浏览别的分支不改变当前续写分支。中文搜索采用当前可见路径内的子串匹配，支持“沈彻”等两字名；不依赖英文分词。快照读取历史节点的状态，回顾仅摘录筛选范围内的事实。

- **JSON 存档**：schemaVersion 3，包含剧本快照、所有分支、日期、原文、人物、履历、数值、事实、认知、记忆、书签、OOC 与标注，有 SHA-256 完整性校验。默认不导出草稿、密钥、原始网络调试或思考字段。
- **MD / TXT**：所选分支与日期范围的玩家原文、正式正文，不重写或编造过渡。
- **导入 JSON 存档**：支持 v1／v2／v3，旧包先验原 checksum 再兼容转换；严格校验日期、剧本绑定、来源、父链与引用，重映射局内 ID 后创建新档，不覆盖原档。单文件20MB上限；大档案使用数据库备份。
- **Scenario ZIP**：在剧本库导入／导出作者模板，不含游玩历史。经过大小、路径、内容和 Schema 检查后先预览，再确认安装；不会解压到服务器目录。
- **TXT / MD 参考**：只隔离保存原文并根据句长选用无剧情事实的固定风格标签；不检索原始参考，不导入本局历史。无 OCR。
- 记忆可钉住、写笔记、标错。标错保留审计记录并从上下文检索排除；事实本身的改写通过作者修订分支完成，原分支不变。

测试数据在项目 .test-data/ 的独立目录，浏览器截图在 artifacts/。这些目录被 Git 忽略，测试不操作正式数据。完整结果与未测边界见 VERIFICATION.md。

- 剧本：src/scenario/ 定义包、历法、规则、快照、库与导入；packages/dayao_empress/ 保存内置作者数据。src/content/canon.ts 仅为大曜兼容／回归入口，通用运行不能从中补世界设定。
- 人物：src/characters/ 的提案、校验与事件重放支持任意合法种子 ID 与动态 UUID。普通 API 只返回当前节点可见投影；扩展字段需同步 Schema、来源校验、存档迁移与验收。
- 事件：src/domain/rules.ts 的纯函数与 src/engine/validate.ts 的证据校验。新规则需版本迁移与阈值测试；不得让模型直接写分数。
- Provider：实现 src/llm/types.ts 接口，添加官方主机、独立凭据引用、按模型能力表和 mock 契约测试。不把 SDK 类型传进规则层。
- 数据：migrations/ 的版本化 SQL 与 src/storage/repository.ts。升级迁移先备份，保持节点不可变。
- 提示与检索：src/memory/context.ts、src/engine/engine.ts，先隔离可见节点再筛相关记忆，硬性玩家权限始终保留。

当前实现偏向保守：无证据的重大变化留在草稿；不提供自动战争模拟或云同步。Google 非流式 SDK 使用总请求超时，不声称已分别测到连接/首字阶段。Node fetch 不单独暴露 TCP 建连时刻；Chat Completions 生成按总请求与流式首字期限控制，connectTimeoutMs 仅用于模型列表查询的响应等待，不把模型计算时间当成建连时间。上下文预算是字符预算近似，不等于供应商 token 计数；极长档案使用原文检索与场景摘要，未做十万节点性能基准。真实模型的长场景文风、秘密传播与人物一致性需要授权后按 tests/narrative-fixtures/README.md 人工验收。

## 动态人物与身份履历

初始六人是种子人物。剧情中的具名个体、证人、使者、办事者等可由同一轮记忆整理登记，不需要出戏填写人物卡；泛指群体不建档。名字、别名、职位和真实身份变化沿用稳定 ID；同名只提示核对，不自动合并。示例名字与升迁不进入正式开局。

正文、人物、任职、关系、认知与记忆一起校验并原子提交。失败只保留草稿，重试同一请求不会重复创建人物。日常仍是两步模型调用，没有新增必需的第三次调用或数据库服务。Mock 可在新测试卷册中用“请军需吏〈自取姓名〉进来”体验人物登记；复杂履历用确定性集成夹具验收，Mock 不声称拥有真实模型的全部语义能力。

- 顶部“人物簿”支持姓名、旧称、职位和势力搜索，按常驻／关注、近期交集、剧情人物、已提及与离场分组。手机上先显示列表，点入详情后可返回；原有六人侧栏保留。
- 人物页显示已知身份、多项职务、客观关系、单向态度、承诺、履历与原文来源。“提议”“已下令”“已生效”“已到任”“已离任”分别记录；实授、兼任、代理、差遣、荣誉称号分开。称呼不授予权限，远方任命不让人瞬移。
- 女帝的任免、封赏和处罚须有玩家本轮明确命令或祖先节点授权；NPC 建议、假设、否定和传闻不能代替授权。校验是保守的有限语义检查，遇到误判可核对草稿、修订并重试，不能保证自然语言绝无误解。
- “当时”或“往事 → 查看当时状态 → 查看当时人物簿”按那个节点显示，不带未来人物、职务或真名。普通人物接口及上下文预览经服务端裁剪，不把隐藏档案发送给浏览器再用样式隐藏。明确下载离线副本后，断网可查看各节点事先生成的可见人物投影；完整恢复包单独保存，不用于渲染人物卡。未下载的存档需要连接主存档服务。
- “关注人物”和自定义分类仅是显示偏好。配角默认不开放恋爱、没有虚构的 0 好感条，不套用大曜六人触发器。剧本允许时，可在“人物路线设置”确认提升为主要人物、开放该剧本数值；成年且允许恋爱时才能开放路线。这是独立配置节点，保留 ID、关系与记忆，不推进时间，不自动接受亲近或重置已有数值。
- “人物资料纠错”可登记认错人／重复人物、职位、知识、遗漏履历问题，留下可追溯更正；也可从来源前开修订分支，把原输入放回编辑框。原文与旧未来保留。本版不提供静默合并人物或直接覆盖旧事实的按钮。
- “人物参考范围”默认12份详细资料，可调6–40；是软预算，点名和在场人物优先，不限制存档人物总数。简要索引用于解析，详细资料按当前场景取用；履历变化后重建过时人物摘要。

数据库升级到 v2 时，先在数据目录生成 `before-characters-v2-*.sqlite` 完整快照，再在事务中添加人物、事件和纠错索引。旧正文、六人 ID、原数值及记忆引用不重写；没有记录的早年任职过程标为“旧存档导入／细节未知”。迁移失败回滚，不清库。保留的 v1 快照可用 `pnpm restore` 恢复到新目录；用旧应用读取可回到迁移前状态，用新应用读取会再次安全迁移。

本轮数据库升级到 v3，迁移前自动生成 `before-scenarios-v3-*.sqlite` 快照；事务内增加包／快照与人物、世界数值 key/value 索引。旧档绑定大曜快照，正文、人物 ID、数值、记忆引用和分支保持。可恢复 JSON v3 继续接受 v1／v2；完整恢复包包含隐藏状态，阅读版 MD/TXT 只导出采用的原文，忽略配置节点。已有离线旧副本只读映射、不自动回写主存档。
