## 不可破坏的约束

1. 玩家唯一扮演玄天华。固定序章之外不替玩家说话、决定、行动或编造内心。
2. 参考聊天仅供风格参考，不导入为初始存档、不强制复刻故事。无法辨认的截图不允许猜测后录入。
3. 新游戏从原设定三月末深夜御书房开始；六名 NPC 初始值严格一致。
4. 消息轮数、场景次数、游戏日期是三个不同概念；OOC 不更新正史状态。
5. 模型只能提出结构化建议。事实、数值、角色知情范围、事件和分支由本地程序提交。
6. 正式正文、记忆和状态必须一致、原子提交。网络或 JSON 失败只能保留草稿。
7. 当前分支不能看见旧未来、其他存档和非正史参考素材；摘要与检索也必须隔离。
8. 硅基流动、DeepSeek 官方、Google Gemma 都必须有真正 adapter；Google 默认 `gemma-4-26b-a4b-it`，不要改成 Gemini 或其他代理厂商。
9. API Key 只在本机服务使用，不进前端构建、浏览器持久化、普通日志或导出。浏览器输入后清空，默认进程内存保存；`.env.local` 的明文性质必须说明。
10. 不自动调用未知厂商、不自动选择昂贵模型、不在无授权时进行付费真实 API 测试。

## 开发方式

使用 DESIGN.md 的单一技术栈；若现有仓库有合理差异，记录取舍后最小改动。不要未经说明更换框架。先做可运行纵向链路，避免一堆空页面和 TODO。

数据迁移前备份；不得清空用户数据库或覆盖用户已有代码。所有默认值和规格解释写入文档，世界观未知项保留未知。

给每个硬规则写单元测试，给每个 provider 写 mock 契约测试，给存档/分支/事务写集成测试。用 Playwright 验证阅读、自由输入、日期检索与错误恢复。模型自由文案质量不能只靠固定文本断言来声称保证。

外部 API 接口使用当前官方文档，参考 `SOURCES.md` 并在实现时核对。不得把未经核实的模型能力写成 supported。

在交付前实际运行 lint、typecheck、unit/integration tests 和 production build。没有权限、网络、运行环境或凭据时明确报告未执行项；不得把 mock 通过写成真实 API 联调通过。

最后报告如何启动、密钥如何配置、数据在哪、怎样备份恢复、完成和未完成项，以及真实执行过的测试命令及结果。
